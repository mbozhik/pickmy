# HSE МП «Психоанализ и психоаналитическая терапия» — email-шаблоны для Unisender

> Черновой бриф по внешнему заказу (не связан с проектом pickmy). Папка используется только как удобная песочница: в `pickmy` уже настроен `bun run email` → превью-сервер `react-email`, смотрящий на `./src/app/api/email`. Шаблоны этого клиента **не регистрируются** в `route.ts` (там логика транзакционных писем самого pickmy через Resend) — они верстаются отдельно и в финале экспортируются как статический HTML для вставки в Unisender.
>
> Папка называется `hse-unisender` (без ведущего `_`) намеренно: `react-email dev` прячет из сайдбара превью-сервера папки, начинающиеся с `_` — с подчёркиванием шаблоны технически рендерились по прямой ссылке, но не были видны в списке слева. Обычное имя папки — и она аккуратно показывается как отдельная группа над шаблонами самого pickmy.

## 2. Хронология переписки (по скриншотам)

Даты в скриншотах не проставлены, только время — привожу как единый хронологический поток.

1. **Пост в группе**: «всем привет! нужен человек, который сможет сверстать через html красиво шаблон для рассылок, рассылать будем через unisender, оплата договорная, пишите в личку 💙» — плюс стандартная карточка Unisender с объяснением их процесса (загрузить базу → собрать письмо в конструкторе или с нуля → отправить и следить за метриками).
2. **Уточнение по инструменту**: на вопрос «а у ребят случайно не свой конструктор?» — ответ: *«проверю ещё раз, но хотелось бы свои шрифты и цвета поставить, вроде как в стандартном конструкторе нет такой возможности»*. → Значит нужен ручной HTML, а не drag-n-drop блоки Unisender.
3. **Бюджет**: *«нужно несколько шаблонов, бюджет суммарно 10 тыс, что скажешь?»*
4. **Скриншот редактора Unisender**: подтверждает, что письмо можно собирать через код-редактор (иконка `</>` в тулбаре) — то есть готовый HTML можно вставить напрямую, не только собирать блоками.
5. Короткое подтверждение с чьей-то стороны: *«привет! проверила, можно)»* — похоже, согласование бюджета/подрядчика с кем-то ещё внутри программы.
6. **Обсуждение дизайна**: готового макета нет — *«вот дизайна пока нет, сможешь по ТЗ тоже подсобрать? самое основное, цвета, шрифты»*. Ответ: соберём по ТЗ и ключевым элементам, либо по референсам, если найдутся.
7. Alya: *«есть фирстиль»* → присылает PDF **`HSE_MP PP_Visual Identity 2022_2023.pdf`** (48.8 МБ) с комментарием: *«вот фирстиль, но не в классическом его понимании, это скорее концепция стиля»*.
8. **Постановка задачи**: *«рассказываю: шаблоны нужно сверстать для магистерской программы по психологии, ориентировочно такие — анонс нескольких семинаров, анонс одного семинара, ссылка на семинар, ссылка на запись семинара»*.
9. Уточнение с нашей стороны: нужно понимать наполнение (контент-модель) каждого шаблона.
10. Alya: ТЗ ещё не дописано («никак не успеваю его дописать»). **Договорились**: начать с одного шаблона, посмотреть результат, если ок — сделать остальные. Alya предложила «сегодня-завтра» набросать черновой контент для первого шаблона.
11. Последнее сообщение с нашей стороны: «пока тз собирается» — то есть на момент этого брифа работа стоит в ожидании ТЗ/черновика от Alya.

**Статус на сейчас**: ждём от Alya (а) дописанное ТЗ, (б) черновой контент хотя бы для одного шаблона. Договорённость о поэтапной сдаче (1 шаблон → апрув → остальные 3) уже есть.

## 3. Объём работ — 4 типа шаблона

| # | Шаблон | Комментарий |
|---|---|---|
| 1 | Анонс нескольких семинаров | дайджест/подборка — вероятно список карточек событий |
| 2 | Анонс одного семинара | конкретный спикер, тема, дата — есть прямой референс в брендбуке (карточка «Ален Жибо», см. §5) |
| 3 | Ссылка на семинар | письмо-напоминание/доступ к уже анонсированному онлайн-семинару (Zoom-ссылка и т.п.) |

Наполнение (какие поля обязательны в каждом типе — дата, спикер, тема, CTA-кнопка, футер с отпиской) **пока не зафиксировано** — это то самое ТЗ, которое обещала Alya. См. открытые вопросы (§7).

## 4. Технические требования

- **Формат сдачи**: судя по интерфейсу Unisender (скрин с иконкой `</>` в тулбаре), ожидается готовый **HTML-код письма** для вставки в код-редактор Unisender, а не просто картинка/Figma-макет.
- **Кастомные шрифты/цвета** — ровно то, чего не даёт стандартный конструктор Unisender, и то, ради чего клиент вообще ищет верстальщика.
- **Инструмент сборки (наш)**: `react-email` + Tailwind, превью через `bun run email` в этом репозитории (`--dir ./src/app/api/email`) — удобно для live-preview, но финальная поставка клиенту — это результат `render()` в чистый inline-HTML (react-email это умеет из коробки), не сам React-компонент.
- **Ограничение по рендерингу почтовых клиентов** (важно, т.к. фирменный стиль программы — многослойный, с полупрозрачными кругами поверх фото):
  - Web-шрифты (`@font-face`) почти нигде не работают в почте (Outlook/большинство десктоп-клиентов их режут) — рассчитывать нужно на fallback-стек (system-ui / ближайший гарнитуре HSE Sans веб-безопасный аналог).
  - CSS `mix-blend-mode` / прозрачность на фоне работает нестабильно (особенно Outlook на Word-движке). **Рекомендация**: сложные композиции (дуотон-фото + полупрозрачные эллипсы + цветные полосы) собирать заранее как один плоский PNG/JPG (в Figma/Photoshop) и вставлять как изображение, а не пытаться воссоздавать эффект живым CSS в письме. Текст поверх — либо тоже часть картинки, либо HTML-текст, наложенный `position`-ом с осторожностью (риск разъезда в Outlook).
- **Обязательный футер**: ссылка на отписку — стандартное требование Unisender/законодательства о рассылках; в брифе клиента явно не упомянуто, но нужно закладывать по умолчанию.

## 5. Фирменный стиль (из PDF `HSE_MP PP_Visual Identity 2022_2023.pdf`)

PDF на 501 страницу, но полезная часть — первые ~34 страницы (дальше идёт большая галерея референсов). Смотрели полностью первые 34 страницы.

### 5.1 Корпоративный стиль ВШЭ (базовый уровень)
- Официальный брендбук: `hse.ru/info/brandbook`.
- Фирменный шрифт: **HSE Sans**.
- Основной цвет — глубокий синий/navy (используется в круглом логотипе ВШЭ и в приглушённо-синих служебных слайдах брендбука).
- Круглый логотип ВШЭ («ВЫСШАЯ ШКОЛА ЭКОНОМИКИ», щит-книга внутри) — обязателен на материалах.

### 5.2 Собственный стиль программы (это то, что реально используется в постах/баннерах — и то, что нужно повторить в письмах)
- **Эмблема программы**: геральдический герб (лев, конь/пегас, фигура с копьём — мифологический сюжет), всегда в паре со словесным блоком **«ПСИХОАНАЛИЗ И ПСИХОАНАЛИТИЧЕСКАЯ ПСИХОТЕРАПИЯ»** прописными буквами, шрифт с засечками.
- **Композиция карточек** (соцсети, баннеры, обложки) — устойчиво повторяющийся приём:
  1. Вертикальные цветные полосы по краю (похоже на цветовой «штрихкод»/спектр);
  2. Поверх — крупные полупрозрачные пересекающиеся эллипсы/круги, наложенные на чёрно-белую (дуотон) портретную/событийную фотографию;
  3. Крупный белый текст-заголовок поверх цветных блоков, гарнитура — гротеск, жирный, крупный кегль;
  4. Эмблема программы — в углу (чаще верхний правый или левый).
- **Палитра** — насыщенные, глубокие «музейные» тона: тёмно-синий/navy, бордовый/винный, фиолетовый, оливково-горчичный, тёмно-бирюзовый/изумрудный, малиновый/пурпурный. Цвета не фиксированы жёстко — набор варьируется от карточки к карточке, но тональность всегда глубокая/приглушённая, никогда не «плакатно-яркая» (кроме отдельных акцентных карточек — см. ниже).
- **Исключение**: карточка с цитатой Фрейда «Иногда сигара — это просто сигара» использует яркий мультицветный градиент (розовый → оранжевый → бирюзовый → фиолетовый) — вероятно, это акцентный/вирусный формат для цитат, отдельный от основной сдержанной палитры.
- **Фотостиль** (стр. 26, дословно):
  - Основной инструмент — «живые, эмоциональные фотографии программы и её людей» (реальные студенты, преподаватели, события) + дизайнерские композиции на основе этих фото.
  - **Сток запрещён**, кроме портретов исторических личностей и «мэтров психоанализа» (Фрейд и т.п.).
  - Если нужна символическая иллюстрация и нет подходящего кадра — допустимо использовать работы современных художников **с обязательным указанием автора и названия**, и **никогда** — в продающих/продуктовых постах.
- **Референсы настроения** (не для копирования, а как ориентир по духу — телесность, сюрреализм, психоаналитическая символика): Kiki Smith, Louise Bourgeois, Matthew Barney, Urs Fischer.

### 5.3 Позиционирование/тон (коммуникационная пирамида из брифа, стр. 4)
- **Essence (суть)**: «пожизненно развивающиеся профессионалы-практики, меняющие мир к лучшему».
- **Promise (обещание)**: «бесконечный мастер-класс. Живое, постоянно развивающееся психоаналитическое пространство. Ключ от дверей».
- **Values (ценности)**: открытость, интеграция, практико-ориентированность, высокий уровень профессионализма, верность кадру.
- **Tone of voice**: творческие мыслящие, тонко чувствующие, преданные методу, любопытные и любознательные, внимательные, ищущие.
- Ключевая метафора коммуникации: **«это живой процесс»** / «психоаналитическое пространство».

### 5.4 Практический вывод для писем
Стиль программы — насыщенный, многослойный, редакторский (дизайн-версии постов, а не шаблонный конструктор). Буквально воспроизвести его «живым» HTML/CSS в письме дорого и рискованно по рендерингу (см. §4). Разумный компромисс:
- Шапка/герой-блок письма — **готовое сведённое изображение** в фирменном стиле (цветные полосы + дуотон-фото + эллипсы + заголовок), собранное как один PNG.
- Тело письма (текст, детали события, CTA) — чистый HTML/Tailwind, но с цветами и типографикой, взятыми из этой же палитры (тёмно-синий текст, акцентная кнопка в одном из фирменных тонов).
- Эмблема программы — отдельный маленький PNG/SVG в футере или шапке.

## 6. Бюджет и процесс

- **Бюджет**: 10 000 ₽ суммарно, озвучен как ориентир на «несколько шаблонов» — не зафиксировано явно, это за все 4 типа или per-шаблон с возможной доплатой (см. открытые вопросы).
- **Процесс сдачи**: поэтапный — сначала 1 шаблон на согласование, при апруве — доверстать остальные 3.
- **Формат промежуточной сдачи** (по словам пользователя): черновой шаблон отправляется клиенту скриншотом для согласования, до финальной пересылки готового HTML.

Все 4 запрошенных Alya типа шаблона таким образом покрыты. Логотипы (круглый ВШЭ + герб программы) вытащены из PDF (стр. 34, чистый белый фон, высокое разрешение) через `pdftoppm`/`imagemagick`, обрезаны и встроены как base64 в `assets.ts` — вместе с палитрой, реально сэмплированной из цветных композиций брендбука (стр. 18, 23), а не придуманной на глаз.

**Реальные фото людей из PDF намеренно не использовались** — это личные фото конкретных студентов/лекторов программы, вытаскивать их в черновик без спроса не стоит. Вместо фирменного приёма «дуотон-фото + полупрозрачные эллипсы» — плоские цветные блоки и тонкая цветная полоса: тот же дух (насыщенная фирменная палитра, чёткая типографика), но 100% email-safe и без юридических вопросов. Когда придёт реальный контент с фото — шапку `SeminarSingle-A`/`SeminarsDigest` можно заменить на готовую сведённую картинку в полном фирменном стиле (см. §5.4).

**Шрифт**: HSE Sans не используется — это, по всей видимости, закрытый корпоративный шрифт ВШЭ (файла нет и в PDF, лицензия неизвестна), и веб-шрифты в почте всё равно ненадёжны (Outlook их просто не подключает). Вместо этого — системный стек `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`: на Mac/iOS Mail это San Francisco, на Windows/Outlook — Segoe UI, на Android — Roboto. Все три — чистые современные гротески, по характеру ближе к HSE Sans, чем Arial, и рендерятся нативно везде без риска. Для словесного блока эмблемы — `Georgia` (серифная, как в оригинальном лого блоке). Проверено через встроенный в react-email чек-лист «Compatibility» на всех 4 шаблонах: есть только 2-3 косметических предупреждения (border-radius и text-decoration игнорируются в Outlook — кнопки/ссылка там будут чуть менее скруглёнными/подчёркнутыми, но не сломаны), критичных проблем нет.

**Как посмотреть**: `bun run email` (или уже поднят на порту 4500 через `.claude/launch.json`), в сайдбаре превью-сервера — группа `hse-unisender`.

**Готово к показу клиенту** — как черновик-скриншот, ровно в формате, о котором договаривались. Перед показом стоит явно проговорить, что это (а) визуальные и контентные гипотезы, не финальный текст/дата/спикер, (б) фото намеренно не добавлены, ждём реальные, (в) шрифт — ближайший безопасный аналог, не HSE Sans.

### 10.6 Технический каркас Unisender

`materials/unisender-base-skeleton.html` — пустой skeleton-код, который Unisender подставляет в свой code-редактор по умолчанию (получен по прямой просьбе клиента: «код который вот тут внизу скрина»). Ключевое:
- Таблично-верстанная структура (email-safe), максимальная ширина письма — **660px**.
- Мобильные адаптивные классы с префиксом `em-` (`em-narrow-table`, `em-mob-wrap`, `em-mob-width-100perc`, `em-mob-padding_left/right-20`) — это **собственные CSS-классы Unisender**, зашитые в их рендер-движок, отвечают за адаптив на `max-width: 660px`. При адаптации шаблонов под их редактор эти классы, видимо, нужно **переиспользовать/встраивать**, а не только полагаться на свои inline-media-запросы из `react-email`.
- MSO-условные комментарии (`<!--[if (gte mso 9)|(IE)]-->`) для Outlook — уже заложены в их каркас.
- Скрытый preheader-блок с zero-width-space заполнителем — паттерн Unisender для preview-текста письма.

Один из черновиков уже был адаптирован под этот каркас и отправлен клиенту («так подойдет?» → «да, так норм», 23:24–23:41) — **какой именно шаблон адаптировался, в переписке не зафиксировано**, сама адаптированная версия в репозитории пока не сохранена отдельным файлом (см. открытые вопросы).
